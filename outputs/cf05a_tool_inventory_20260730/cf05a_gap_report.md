# CF-05A 工具清单预审与缺口报告

## 结论

120项规划清单的ID和规划API函数名均唯一，但当前代码注册表只覆盖17项；其余103项尚未实现。CF-05正式接受数仍为0，因此本轮结果不能用于宣称已有120个可调用工具。

## 关键发现

- 规划条目：120
- 代码已实现且已有基线回归/输入鲁棒性证据：17
- 仅规划未实现：103
- 初步未发现签名重叠：95
- 需家族复审：25项，分布在9个家族
- 名称完全重复：0
- 规划API函数名完全重复：0
- 规划API名与当前运行时命名需要显式映射：17
- CF-05正式接受：0

## 命名契约问题

当前存在三个命名表面：

1. 规划清单API函数名，例如 `convert_units`；
2. 内部 `api_name`，例如 `model_a001`；
3. LLM实际函数调用名，例如 `A001`。

三者不妨碍当前17项运行，但在构造50/100/120 Full Schema、日志追踪和论文复现前，应冻结一张一一映射表。

## 家族复审

同场景、同类型、同核心方法、同主要输入和同主要输出的条目被标记为“需家族复审”。该标记不是重复判定；专业复审需要比较具体输出Schema、适用域、失败模式和依赖，决定保留独立、合并为operation或拒绝部分条目。

## 废弃页面处理

页面是否存在、是否废弃，不作为工具有效性的判断依据。有效性证据按“代码注册 → 正常回归 → 边界测试 → 专业适用域审核 → CF-05审批”逐级确认。
