# CF-05 E3开发方法冻结决策候选

## 建议结论

建议项目负责人批准：

> 冻结当前 `full_schema`、`lexical_top5`、`dense_top5` 和 `hierarchical` 四种候选方法及统一传输策略，停止针对已使用开发任务继续调参。

该建议只冻结方法候选，不把CF-05标记为`passed`，不开放独立验证集，也不允许确认性H3/H4推断。

## 证据基础

- A003受控切片96单元全部正确，证明四方法管线和0/8近邻评分可运行，但存在天花板效应；
- A001/A002/A004/B019混合现实切片64单元全部正确，证明多目标和17/120工具执行可运行，但仍有天花板；
- A004难例三重复共144单元，47/48配对单元稳定正确，1个稳定多调用失败；
- A002/A003三重复共576结果，186/192配对单元稳定正确、2个稳定失败、4个波动；
- A004后置探针10/10正确且门控无误拦截。

继续在这些开发任务上优化会提高过拟合风险，因此当前证据更适合支持“停止调参并固定方法”，而不是继续追求开发集满分。

## 冻结对象

- Full Schema：按冻结工具池顺序暴露全部函数Schema；
- Lexical Top-5：加权Unicode n-gram BM25，`top_k=5`；
- Dense Top-5：冻结的BGE small中文向量模型、查询策略、文档渲染和余弦排序，`top_k=5`；
- Hierarchical：冻结的域—能力—适用域层次及权重，`top_k=5`；
- 统一传输：`thinking disabled`、`temperature=0`、`max_tokens=256`、`tool_choice=auto`、每单元一次、无自动重试、不执行工具、保留原始响应。

具体文件及SHA-256由候选包中的`cf05_method_artifact_manifest.json`固定。

## 残余风险

1. 复杂请求在120工具规模下可能同时调用等价或重叠端点；继续按ITT错误计分，不进行事后择一修复。
2. 五个目标工具的完整0/4/8受控近邻矩阵尚未形成闭环，这是CF-05整体通过前的唯一当前阻断项。
3. 多个开发切片存在100%天花板，不能用于证明方法优劣。
4. 120目录中只有5个工具属于已验证可执行核心，论文必须区分“Schema路由规模”和“已验证计算引擎数量”。

## 批准后的下一步

批准本候选后：

1. 生成项目负责人采用记录并绑定本候选manifest；
2. 不再修改四种方法或已消费的开发任务；
3. 离线审计五个目标的0/4/8近邻覆盖，缺失项只允许通过预定规则补齐，不根据模型表现选池；
4. 覆盖审计通过后，再决定CF-05是否可标记为`passed`；
5. 独立验证集仍需单独开启门，不由本决策自动授权。
