## 1. 研究目标

### 1.1 研究背景与问题缺口

现有通用工具调用研究已经分别覆盖“是否使用工具”“选择哪个工具”、大规模API检索、多轮状态交互和轨迹评价。例如：

- [MetaTool](https://arxiv.org/abs/2310.03128)研究工具使用意识与工具选择；
- [ToolLLM](https://arxiv.org/abs/2307.16789)研究超大规模API检索与使用；
- [ToolSandbox](https://arxiv.org/abs/2408.04682)研究信息不足、状态依赖、禁止事件和动态轨迹；
- [τ-bench](https://arxiv.org/abs/2406.12045)研究工具—用户多轮交互与重复运行可靠性。

本研究不把“拆分工具调用阶段”本身作为创新，而聚焦通用API研究尚未充分覆盖的冶金科学计算差异：

1. 回答是否必须具有外部、可复核的专业计算证据；
2. 计算必要性与当前执行准备度并不等价；
3. 科学工具除参数格式外，还受体系、相态、温度、压力、成分、数据库和模型假设约束；
4. 大规模工具中的主要困难可能来自功能重叠但适用域不同，而非仅是名称相似。

### 1.2 总目标

面向大规模冶金专业计算工具库，研究大语言模型的工具调用必要性、调用边界及工具选择与组合机制，构建可计算、可校验、可追溯的冶金智能体系统。

通俗表述为：

> 让大模型在冶金问题上不乱算、不漏算、选对工具、算得可信。

### 1.3 主论文目标

主论文聚焦：

1. 在不暴露具体工具 Schema 时识别专业计算证据需求；
2. 将计算必要性、粗粒度执行准备度和具体工具适用性解耦；
3. 研究工具规模与科学功能相似度对工具选择的影响；
4. 验证层次化路由在 120 个专业工具环境中的性能与成本优势。

### 1.4 主论文排除范围

以下内容保留为下游验证、系统扩展或第二条论文线，不作为主论文需要同时充分证明的核心创新：

- 复杂多工具依赖图规划；
- 中间变量传播和异常工具替代；
- 单位、守恒和物理规律的完整轨迹验证；
- 高炉、炼钢、连铸等完整工程样板的效果归因；
- 工具训练、模型微调和新的基础模型架构。

这些模块可以出现在端到端案例中，但不与 RQ1—RQ3 争夺主要篇幅。

## 2. 核心概念的操作性定义

### 2.1 外部专业计算证据

外部专业计算证据是由可执行的专业工具、数据库或确定性计算服务生成，并且具有以下属性的结果：

- 输入参数可记录；
- 数据或公式来源可说明；
- 工具版本可识别；
- 计算过程可重复；
- 输出可接受数值、适用域或物理规则检查。

大模型凭记忆直接生成的数值，即使碰巧正确，也不属于外部专业计算证据。

### 2.2 证据需求

`evidence_requirement`描述任务本身对外部计算证据的需求，而不考虑当前平台是否存在相应工具：

- `none`：可靠回答不依赖外部专业计算证据；
- `optional`：直接推导和工具计算均可能合理，取决于精度、风险、可复现性和平台政策；
- `required`：可靠回答必须依赖外部数据、专业模型、复杂计算或可审计证据。

### 2.3 Schema 盲

Schema 盲阶段不得看到：

- 具体工具名称或工具 ID；
- 函数描述；
- 参数 Schema；
- 候选工具数量；
- 工具排序；
- 具体公式、适用温度或数据库版本；
- 暗示正确工具的工具级特征词。

Schema 盲阶段可以看到：

- 用户问题和对话上下文；
- 固定的平台政策；
- 通用冶金知识；
- 实验条件允许时的粗粒度能力目录。

### 2.4 粗粒度能力目录

粗粒度能力目录只允许包含一级能力类别：

- 热力学计算；
- 反应动力学；
- 物料与能量衡算；
- 过程状态预测；
- 优化求解；
- 传热、凝固与组织演化；
- 排放与资源评价。

目录不得包含具体工具名、公式名、参数名、物质体系、温度范围、数据库名称或候选数量。目录版本、顺序、描述长度和可见能力必须在实验前冻结。

### 2.5 合法动作

系统动作集合为：

- `answer`：直接回答；
- `call`：调用专业工具；
- `clarify`：向用户补充询问；
- `refuse`：明确拒绝当前请求；
- `escalate`：转人工或要求高风险审核。

当任务存在多个合理动作时，以 `allowed_actions` 集合表示。能力评价不得将集合中的合法动作错误判为失败。

### 2.6 政策动作

`policy_expected_action`是根据 `policy_mode`、证据需求、边界状态和风险等级确定地产生的单一动作。能力合理性和平台政策服从性必须分别评价。

## 3. 系统阶段与信息边界

正式方法链为：

```text
用户问题
→ ① Schema盲证据需求判断
→ ②A 粗粒度信息、能力和风险门控
→ ③ 分层候选工具检索
→ ②B 工具级参数完整性与科学适用域检查
→ ④ 单工具执行或依赖图编排
→ ⑤ 执行校验、证据链和最终回答
```

| 阶段 | 可见信息 | 不可见信息 | 主要输出 |
|---|---|---|---|
| ① 证据需求 | 问题、上下文、政策 | 工具名、Schema、候选集 | `none/optional/required` |
| ②A 粗门控 | 阶段①结果、粗能力目录、风险政策 | 工具级参数和适用域 | 基本信息是否缺失、能力类别是否存在、是否高风险 |
| ③ 检索 | 问题、能力类别、工具元数据索引 | 工具执行结果 | Top-K候选与召回证据 |
| ②B 精门控 | 候选工具卡、参数Schema、适用域 | 未召回工具的完整Schema | 参数完整性、适用性、换用/追问/拒绝 |
| ④ 执行 | 已通过门控的工具和参数 | 无关工具 | 调用结果和执行轨迹 |
| ⑤ 校验 | 参数、结果、规则和来源 | 无 | 校验状态、证据链、最终回答 |

②A与②B不得合并为一个不可解释的单次判断。

## 4. 研究问题与可证伪假设

### RQ1：Schema 暴露如何影响专业计算证据需求判断？

#### H1：Schema 暴露效应

与 Blind 条件相比，完整工具 Schema 暴露将提高总体调用倾向，降低部分 `required` 任务的工具绕过率，但同时提高 `none`、`optional`普通模式和信息不足任务的过度或提前调用率。

若 Full Schema 与 Blind 在调用倾向和分类错误上均无稳定差异，则 H1 不成立。

### RQ2：双层边界门控能否改善调用决策？

#### H2：双层边界门控

与全量 Function Calling 和单一提示词规则相比，Schema 盲证据门控与双层准备度检查将降低工具绕过、过度调用、提前调用和越界调用的宏平均错误率，同时保持 `required + answerable + information_status=sufficient + capability_status=available + risk_status=normal`任务的调用召回率。

Full Boundary相对于预先固定的`Direct FC`基线，在上述任务上的调用召回率非劣界值为`-5`个百分点。使用“Full Boundary − Direct FC”差值的单侧95%置信区间；只有置信区间下界大于`-0.05`时才判定非劣。

5个百分点表示项目可接受的最大调用召回损失，必须在正式实验前由项目组和冶金专家确认。若Direct FC的绝对调用召回率低于80%，不得仅凭相对非劣得出方法有效结论；Full Boundary还必须达到80%的绝对召回下限。“最佳非Oracle基线”只作为探索性比较。

### RQ3：工具规模和科学功能相似度如何影响路由？

#### H3：规模与相似度效应

工具选择性能将随工具池规模增加而下降；功能重叠但适用域不同的干扰工具造成的性能损失将大于无关干扰工具和单纯词法相似工具。

若工具规模、干扰类型及其交互项均无稳定效应，则 H3 不成立。

#### H4：层次化路由

与全量 Schema、词法 Top-K 和单纯向量 Top-K 相比，层次化路由在 120 工具条件下具有更小的工具选择性能下降，并减少 Schema Token和模型推理延迟；端到端延迟是否下降作为独立结果检验，不预设方向。

H4的主要效应量固定为端点下降值：

```text
ΔAccuracy_method = Accuracy_method,120 − Accuracy_method,17
```

数值越接近0表示规模稳定性越好。正式统计检验使用`method × log(tool_pool_size)`交互项；工具规模作为分类变量的结果只用于检查非线性。

## 5. 实验总览与主要指标

| 实验 | 对应问题 | 主要指标 | 次要指标 |
|---|---|---|---|
| E1 Schema暴露 | RQ1/H1 | `evidence_requirement`三分类宏F1 | Balanced Accuracy、混淆矩阵、合法动作命中率、调用倾向、绕过率、过度调用率 |
| E2 双层门控 | RQ2/H2 | 四类关键错误宏平均率 | 五类动作宏F1、政策一致率、正确追问率、调用召回率 |
| E3a 规模与相似度 | RQ3/H3 | 可接受工具选择准确率 | 高相似度误选率；检索方法另报MRR、nDCG、Recall@5 |
| E3b 层次化路由 | RQ3/H4 | `ΔAccuracy = Accuracy120 − Accuracy17` | `method×log(pool_size)`交互、Schema Token、总Token、检索延迟、模型延迟、端到端延迟 |

主要指标在协议冻结后不得变更。其他指标只能作为次要指标或探索性分析报告。

### 5.1 四类关键错误

E2主要指标定义为以下四项条件错误率的宏平均，越低越好：

1. 工具绕过率：`required + answerable + sufficient + available + normal`任务选择`answer`；
2. 过度调用率：`none + answerable + normal`任务选择`call`；
3. 提前调用率：`risk_status=normal`且问题语义不完整，或必须调用但缺少执行信息时选择`call`；
4. 越界调用率：`risk_status=normal`且明确超适用域或能力不可用时选择`call`。

各错误率分别使用其适用样本作为分母，再取宏平均，避免多数类别掩盖高风险错误。
`risk_status=review_required`任务不进入上述四类调用错误率和调用召回率分母，而单独评价`escalate`正确率。

## 6. E1：Schema 暴露效应实验

### 6.1 实验对象

- 数据：Track A调用边界集；
- 核心样本：最小差异问题组；
- 工具池：冻结的17工具池；
- 模型、温度、系统政策和推理预算保持一致；
- 同一问题在不同信息暴露条件下重复测试。

E1的每个条件只输出两个结构化判断：

```text
evidence_requirement: none | optional | required
predicted_action: answer | call | clarify | refuse | escalate
```

E1不实际执行任何工具。所有条件使用同一结构化输出Schema。Full Schema优先通过原生工具字段暴露Schema并设置`tool_choice=none`；即使模型预测`call`，也只记录动作，不发送函数调用请求。若供应商不支持禁止调用，则改用标准化只读Schema序列化，并将该实现作为独立实验版本，不与原生字段结果混合。

### 6.2 实验条件

| 条件 | 信息暴露 |
|---|---|
| Blind | 问题和政策，不提供能力目录和工具Schema |
| Blind-Length-Control | Blind信息 + 与Full Schema长度近似的中性无任务信息文本 |
| Taxonomy | 问题、政策和冻结的一级能力目录 |
| Full Schema | 问题、政策和标准化17工具Schema |

`Blind-Length-Control`用于区分“Schema语义诱导”和“单纯上下文变长”。

### 6.3 控制要求

- Full Schema使用统一工具卡模板；
- 工具排序按预先登记的随机种子变化；
- Blind-Length-Control不得包含冶金能力、工具或动作暗示；
- 所有条件使用同一用户问题；
- 所有条件使用同一结构化响应格式；
- 不在系统提示词中直接写入该样本的预期动作；
- `optional`样本按合法动作集合评分，并单独报告动作分布。

### 6.4 分析

- 主要指标：证据需求三分类宏平均F1；
- 同时报告三分类Balanced Accuracy和完整混淆矩阵；
- 方向性错误至少包括`none→required`、`required→none`、`optional→required`和`required→optional`；
- 主要比较：Blind vs Full Schema；
- 语义泄漏控制：Blind-Length-Control vs Full Schema；
- Taxonomy增益：Blind vs Taxonomy；
- 合法动作集合命中率只作为动作层次的次要指标；
- 对调用倾向、绕过和过度调用分别报告方向与置信区间。

### 6.5 120工具确认性子实验

E1主实验使用17工具以控制Schema内容和长度。另从核心最小差异组中预注册一个确认性子集，在120工具条件下复现Blind、Blind-Length-Control和Full Schema比较。该子实验用于确认Schema暴露效应能否延伸到大规模工具环境，不替代17工具主实验。

## 7. E2：双层边界门控实验

### 7.1 单变量消融链

基线比较线：

```text
Direct FC
Prompt Rule
```

`Prompt Rule`作为独立启发式基线参与最终比较，不属于相邻单变量方法消融链。

方法消融线：

```text
Direct FC
→ Blind Gate
→ Blind + Coarse
→ Blind + Coarse + Retrieval
→ Full Boundary
```

| 方法 | 证据门控 | ②A粗判断 | 层次化检索 | ②B工具检查 |
|---|---:|---:|---:|---:|
| Direct FC | 否 | 否 | 否 | 否 |
| Prompt Rule | 提示词内 | 否 | 否 | 否 |
| Blind Gate | 是 | 否 | 否 | 否 |
| Blind + Coarse | 是 | 是 | 否 | 否 |
| Blind + Coarse + Retrieval | 是 | 是 | 是 | 否 |
| Full Boundary | 是 | 是 | 是 | 是 |

只对方法消融线中的相邻方法作单变量归因。除新增模块外，模型、提示内容、候选池、最大调用数和执行器保持一致。

### 7.2 方法解释

- `Direct FC`：直接暴露全量工具，使用自动工具选择；
- `Prompt Rule`：在Direct FC基础上增加文字边界规则；
- `Blind Gate`：先进行Schema盲证据需求判断，之后使用相同全量工具；
- `Blind + Coarse`：增加粗粒度信息、能力和风险门控；
- `Blind + Coarse + Retrieval`：确认可计算后使用层次化检索；
- `Full Boundary`：增加候选工具级参数和适用域检查。

### 7.3 Oracle 1：边界上界

人工提供正确的：

```text
evidence_requirement
answerability
information_status
capability_status
risk_status
boundary_flags
policy_expected_action
```

Oracle不参与普通方法排名，只用于回答：当边界判断完全正确时，后续检索和执行的理论上限是多少。

### 7.4 主要分析

- 四类关键错误宏平均率；
- Full Boundary相对固定`Direct FC`的`required + answerable + sufficient + available + normal`调用召回率非劣性检查；
- 使用单侧95%置信区间和`-5`个百分点非劣界；
- Direct FC低于80%绝对召回时，同时检查Full Boundary是否达到80%绝对下限；
- 合法动作集合命中率；
- 政策一致率；
- `review_required`任务的正确转人工率；
- 错误按证据需求、准备度、风险和来源分层报告。

## 8. E3：工具规模、相似度与层次化路由

### 8.1 正式工具规模

正式规模固定为：

```text
17、50、100、120
```

120是主论文中“100+工具”的唯一正式上限。工具清单必须在实验前通过独立工具审计；若合格工具不足120，只能在正式数据采集前通过协议修订调整，不得在看到实验结果后改变规模。

### 8.2 固定目标、嵌套扩池

同一任务的目标工具、问题文本和标准答案保持不变，只增加干扰工具：

```text
Pool-17 ⊂ Pool-50 ⊂ Pool-100 ⊂ Pool-120
```

每个目标任务、工具规模和干扰条件生成5套预注册工具池：

```text
A、B、C、D、E
```

每套工具池记录：

```text
tool_pool_id
pool_family_id
random_seed
tool_ids
pool_design
near_neighbor_type
near_neighbor_count
near_neighbor_ratio
distractor_composition
similarity_distribution
schema_token_count
tool_order
```

目标工具家族和`acceptable_tools`保存在Track B任务金标准中；工具池元数据不保存方法输出，模型检索排名和选择结果只写入实验运行表。

### 8.3 干扰类型

正式工具池分为三类：

1. `controlled_dose`：用于H3主要因果分析；
2. `pure_type_exploratory`：纯类型池，只在17、50或实际近邻上限内构造；
3. `mixed_realistic`：按真实工具库相似度分布构造，用于外部有效性。

| 干扰层级 | 操作性定义 |
|---|---|
| 低：无关干扰 | 与目标任务属于不同一级能力和不同科学对象 |
| 中：词法相似 | 名称或描述共享术语，但科学功能不同 |
| 高：功能重叠 | 能力相近，但适用体系、相态、温压范围、数据库或模型假设不同 |

高相似度工具必须由冶金专家确认其“功能相近但不能在当前任务中互换”。

`controlled_dose`在17、50、100、120四个规模均使用固定近邻剂量：

```text
near_neighbor_count = 0、4、8
near_neighbor_type = lexical或functional_overlap
```

除指定的0、4或8个近邻外，其余位置由同一版本的无关干扰基底补齐。这样总工具规模与高相似干扰数量可以独立控制，不要求构造不现实的120工具纯高相似度池。

H3中“功能重叠比词法相似造成更大损失”的确认性比较，只使用同时拥有至少8个词法近邻和8个功能近邻的目标工具。近邻不足的目标可以进入4剂量或现实混合池，但不进入该确认性配对比较。

`pure_type_exploratory`不强制达到100或120，其最大规模由真实可用近邻数量决定，不用于主论文的17→120规模效应结论。

正式实验单元为：

```text
目标任务
× 工具规模
× pool_design
× near_neighbor_type
× near_neighbor_count
× 工具池重复A—E
× 模型运行重复
```

如果某个目标工具没有足够多的词法或功能近邻：

- 不得将无关工具改标为高相似度；
- 该目标工具不进入无法满足的确认性剂量条件；
- 仍可进入`mixed_realistic`工具池；
- 由不平衡设计和混合效应模型处理不同目标工具的可用条件；
- 缺失条件及原因必须在工具池清单中记录。

### 8.4 Schema控制

- 工具卡使用同一渲染模板；
- 功能描述限制在统一长度区间；
- 使用真实但规范化的语义名称；
- 所有方法使用完全相同的工具名称；
- 工具名不得直接复用任务样本中的完整目标短语；
- 工具名称和描述的可辨识度分别记录并审计；
- 参数数量和Schema Token作为协变量记录；
- 工具顺序由登记种子随机化；
- 正确工具的位置在不同池中平衡；
- 工具描述详细程度和适用域字段完整度保持一致；
- 不能删除真实必要参数以人为缩短Schema。

### 8.5 路由方法

| 方法 | 描述 |
|---|---|
| Full Schema | 将当前规模的全部Schema交给大模型 |
| Lexical Top-5 | 词法/模型卡关键词召回，M4.6B作为先导实现 |
| Dense Top-5 | 向量检索Top-5 |
| Hierarchical Top-5 | 领域→能力→适用域→候选工具的层次化路由 |
| Oracle Top-5 | 人工构造始终包含正确工具的理想候选集 |

所有Top-K方法正式固定为`K=5`。如需研究其他K值，只能在开发集进行，并作为探索性结果。

层次化路由的层级结构固定为“一级冶金领域→科学能力类别→体系与相态→工具级候选”。具体检索模型、融合权重和阈值只允许在开发集确定，正式测试前必须生成不可变方法版本和配置哈希。

### 8.6 Oracle 2：候选集上界

Oracle Top-5用于回答：

- 候选集包含正确工具时，大模型内部选择上限是多少；
- 当前错误来自召回阶段还是候选内区分阶段；
- 参数生成错误是否独立于路由错误。

Oracle不参与普通方法的效率排名。

### 8.7 主要分析

- E3a：工具规模、相似度及其交互对可接受工具选择准确率的影响；
- E3b：计算每种方法的`ΔAccuracy = Accuracy120 − Accuracy17`并进行方法间比较；
- 正式推断模型以`method × log(tool_pool_size)`交互项检验下降趋势差异；
- 检索层只比较Lexical、Dense和Hierarchical，报告Recall@5、MRR、nDCG和候选数量；
- Full Schema没有检索排序，不计算MRR；Oracle候选集也不参与MRR和nDCG排名；
- 最终选择层比较所有方法，报告可接受工具选择准确率、高相似度误选率和拒绝/追问正确率；
- Lexical、Dense、Hierarchical和Oracle的Top-5必须使用完全相同的第二阶段模型、提示词、工具卡格式和选择策略；
- 分别报告检索时间、模型推理时间和端到端时间；
- 单独报告高相似度工具中的适用域误选。

### 8.8 120 Full Schema可行性门槛

正式冻结前必须完成只验证接口能力、不用于效果结论的工程检查：

- 17、50、100、120个函数Schema均能被目标模型API接受；
- 请求不超过供应商函数数量和上下文限制；
- 原生Function Calling和文本工具目录不得在同一主比较中混用；
- 所有方法复用同一版本的工具描述内容；
- Schema Token计算器和编码版本固定；
- 记录序列化后的请求Token、参数数量和总Schema长度；
- 延迟拆分为本地检索、请求构建、模型响应、工具执行和端到端时间；
- 超限、截断或供应商拒绝视为基线不可执行，不得静默减少工具数量。

若120 Full Schema不可执行，应在正式数据采集前修订基线定义并重新评审H4；不得在看到效果结果后临时改用文本目录。

## 10. 工具独立计数与审计

一个对象只有同时满足以下条件，才能计为一个独立工具：

1. 有独立且可执行的函数或服务入口；
2. 具有明确且不能完全由已有工具替代的科学能力；
3. 有独立输入输出契约；
4. 有明确适用范围；
5. 有至少一组正常测试和边界测试；
6. 参数配置、公式常数或数据库版本差异不自动计为新工具；
7. 同一算法的不同版本登记为版本，不重复计数；
8. 纯包装函数不单独计数，除非承担独立科学计算语义。

120工具清单由一名计算机方向成员和一名冶金方向成员独立审核，冲突由项目负责人裁决。审计结果和排除原因必须保留。

## 11. 重复、随机化与运行控制

### 11.1 重复次数

- 开发和排错：每条件3次；
- 核心论文实验：每条件至少5次；
- 先导实验显示高波动的任务：8—10次；
- 重复次数不得根据正式结果方向临时增加或减少。

高波动任务的判定规则在先导阶段确定，并在正式运行前冻结。

### 11.2 运行控制

- 固定模型名称和供应商版本记录；
- 固定温度、Top-K、最大轮次、最大调用数和最大输出Token；
- 记录系统提示词哈希和工具目录版本；
- 记录每次运行时间、API响应ID和Token；
- 运行顺序按预注册随机种子打乱；
- 不因单次不利结果手工重跑；
- 供应商故障按预定义故障标准处理并完整报告。

### 11.3 多次运行可靠性

除平均成功率外，报告同一任务多次运行的稳定性，包括：

- 全部重复均成功的任务比例；
- 至少一次成功的任务比例；
- `pass^k`或等价一致成功曲线；
- 动作和工具选择在重复间的一致性。

### 11.4 主要指标的重复汇总

主要分析固定采用：

1. 每个`run_repeat`在完整数据集上分别计算三分类宏F1、合法动作命中率、四类错误率和工具选择准确率；
2. 报告各重复指标的均值、标准差和95%区间；
3. 任务层Bootstrap时以问题组为簇，并在每个抽中的任务簇内保留该任务的全部运行重复；
4. 方法间重复通过相同`run_repeat`、任务和工具池进行配对；
5. 不使用多数投票作为主要结果；
6. 多数投票和“至少一次成功”只作为探索性稳定化分析；
7. 混合效应模型将`run_repeat`作为重复观测层，并加入随机截距。

不得把“任务×运行”简单当作彼此独立的样本扩大有效样本量。

### 11.5 延迟定义

```text
retrieval_latency
= 本地或远程候选检索的总时间

model_latency
= 证据门控模型时间
+ 粗门控模型时间
+ 候选内选择模型时间
+ 其他属于该方法的模型调用时间

end_to_end_latency
= 从接收任务到产生最终动作或工具选择的墙钟时间
```

模型调用并行时，同时记录各调用耗时之和与关键路径墙钟时间；主延迟指标使用墙钟时间，耗时之和作为资源消耗指标。

## 12. 统计分析计划

### 12.1 置信区间

- 对任务样本进行簇级Bootstrap；
- 最小差异问题组作为Bootstrap簇；
- 工具路由实验同时考虑目标工具或工具家族的簇结构；
- 报告95%置信区间。

### 12.2 配对检验

- 重复二元结果的主要推断使用包含任务和`run_repeat`结构的混合效应逻辑回归；
- McNemar仅作为敏感性分析，在每个预注册配对`run_repeat`上分别执行，并使用Holm方法校正；
- 宏平均F1和合法动作集合命中率：配对Bootstrap或置换检验；
- Token、检索延迟、模型延迟和端到端延迟：分别使用Wilcoxon配对符号秩检验；
- 多重次要比较使用Holm方法校正。

### 12.3 混合效应模型

规模与相似度实验使用混合效应回归，基本结构为：

```text
结果
~ 方法
+ log(工具规模)
+ 近邻类型
+ 近邻数量
+ 方法×log(工具规模)
+ 方法×近邻类型
+ 方法×近邻数量
+ 任务复杂度
+ Schema Token
+ 随机效应（问题组、目标工具、工具家族、工具池、run_repeat）
```

二元成功结果使用混合效应逻辑回归；MRR等连续或有界指标根据分布选择合适模型。

### 12.4 功效分析

正式样本量在协议冻结后、正式测试前使用独立先导数据估计：

1. 预设显著性水平`α=0.05`；
2. 统计功效目标不低于`0.80`；
3. E1和E2的最小实际关注差异为5个百分点；
4. E3关注17→120工具的性能下降及方法交互；
5. 考虑问题组和工具家族造成的设计效应；
6. 先导样本不得进入最终测试集；
7. 功效分析脚本、参数和输出纳入版本控制。

正式测试前必须生成：

```text
docs/experiments/sample_size_addendum_v1.0.md
```

该附录至少记录先导样本、效应量、设计效应、最终样本量、各类别最低样本量、重复次数，以及是否看过正式测试结果。

## 13. 评分原则

### 13.1 能力评分

若：

```text
predicted_action ∈ allowed_actions
```

则合法动作集合命中。

### 13.2 政策评分

若：

```text
predicted_action = policy_expected_action
```

则政策一致。

两项必须分开报告。

### 13.3 路由评分

当：

```text
selected_tool ∈ acceptable_tools
```

则工具选择正确。不得因选择了不同但科学上等价的工具而判错。

### 13.4 过程与答案分离

至少分别报告：

- 动作决策；
- 候选召回；
- 工具选择；
- 参数和适用域；
- 轨迹合规；
- 执行结果；
- 最终回答。

最终答案正确不能抵消越界调用或伪造参数；路径错误也不应自动抹去答案语义评价。
