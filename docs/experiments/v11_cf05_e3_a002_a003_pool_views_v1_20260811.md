# CF-05 E3：A002/A003 17/120 工具池视图与池内金标候选

## 本轮目的

将已采用的 A002/A003 工具家族治理规则落实到可运行的 17/120 工具规模开发输入中，并在不调用外部模型的前提下，复核每个池内可直接满足任务的工具。

## 冻结设计

- 任务：8 组最小差异问题，共 16 条；每组仅改变请求输出（元素计量或摩尔质量）。
- 工具池：复用既有 A003 `controlled_dose / lexical-8` 池。
- 规模与重复：17、120 工具，A/B 两个池重复，共 4 个视图。
- 两个家族端点 A002、A003 在全部视图中均可见。
- 仅接受 canonical input 恰为 `formula` 且能一次执行直接满足全部冻结输出检查的候选端点。
- 不将派生或多步工具纳入主端点正确率。

## 复核结果

四个池的逐工具 Schema 筛查得到四个同签名端点：A002、A003、E3C002、E3C018。

- 元素计量任务：17 工具池主可接受集合为 `{A002}`；120 工具池因包含并验证通过 E3C002，集合为 `{A002, E3C002}`。
- 摩尔质量任务：主可接受集合为 `{A003}`；A002 只进入 Alternative Success 与 Scientific Success，不进入 Primary Endpoint Accuracy。
- E3C018 要求显式同位素标记，对当前中性化学式任务均不直接适用，16 次本地检查均未通过。

共执行 32 次候选工具本地单次验证，没有调用 DeepSeek 或其他外部 API。

## 状态边界

本轮冻结的是四个指定开发池的池内评分候选，不是 120 工具正式金标准，也不改变既有确认性数据。产物仍为开发候选，`CF-05=in_progress`、`Core Frozen=false`。

下一门是据此构建未授权的开发运行开启包；在用户单独授权前，不发送任何外部 API 请求。
