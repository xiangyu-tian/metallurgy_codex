# CF-05 E3工具选择传输政策v1

R1与R1.1单变量配对证明，未在实际请求载荷中显式关闭thinking会让长Schema条件出现输出预算截断，并伪装成工具规模效应。因此后续E3工具选择实验采用以下传输政策。

## 请求要求

- 每个实际wire payload必须显式包含`thinking={"type":"disabled"}`；仅在适配器配置中声明不够。
- 默认`max_tokens=256`、`temperature=0`、`tool_choice=auto`。
- 修改token预算必须创建新的开启包版本，不能事后修改或覆盖既有运行。
- 载荷必须绑定SHA-256，且不得包含API Key或Authorization信息。

## 运行要求

- 每个单元一次尝试，自动重试关闭。
- 不执行模型返回的冶金工具。
- 保留原始响应、usage、finish reason和reasoning审计信息。
- 即使发生长度截断或参数JSON不完整，也作为终态失败保存，不自动修复。

## 解释要求

- R1只可作为传输层诊断，不能用于17→120规模效应推断。
- R1.1证明当前16条开发任务在修正传输后未观察到A002/A003混淆，但不能据此形成确认性H4结论。
- 若显式关闭thinking后仍观察到规模下降，才进入路由或Schema规模机制分析。

本政策约束后续E3开发运行和候选确认性开启包，但本身不授权任何外部API调用，也不把`CF-05`或`Core Frozen`标记为完成。
