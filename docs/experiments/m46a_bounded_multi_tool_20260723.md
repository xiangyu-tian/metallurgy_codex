# M4.6A 有界多工具依赖链实验

## 目标

在 M4.5 单轮 autonomous 基线上增加有界多轮工具调用，验证模型能否利用前一步执行结果生成下一步参数，同时防止无限重试。

本阶段只改多轮编排，不增加候选模型召回。M4.5 单轮策略仍可通过 `m4.5-v1` 显式运行，作为固定对照。

## 循环契约

- 仅 `m4.6-v1 + autonomous` 启用多轮；
- 最多 3 个工具轮次；
- 累计最多处理 5 次工具调用；
- 同一模型与规范化参数形成调用签名，签名重复时停止；
- 达到边界后关闭工具，基于已有结果生成最终回答；
- forced 仍为单轮强制调用，direct 仍不提供工具；
- 轨迹记录每轮请求与响应、调用所属轮次、调用签名、停止原因和累计 Token。

停止原因包括：

- `assistant_final`
- `tool_round_limit`
- `tool_call_limit`
- `duplicate_tool_call`
- `forced_single_round`
- `single_round_policy`
- `provider_error`

## 数据集审计与修订

第一次试跑发现，数据集 `1.1.1` 的多工具子集复用了按模型定义的一套默认参数，造成部分问题文本、冻结参数与预期路径不一致。例如：

- CaCO3 问题的冻结化学式仍为 Fe2O3；
- 压力问题错误地指定反应 Gibbs 模型；
- 炉渣、动力学、物流和扩散问题缺少必要数值，却要求必须调用；
- ASCII 反应式与冻结模型实际支持的 Unicode 下标反应式不一致。

因此第一次诊断试跑不用于效果结论。修订后的数据集版本为 `1.2.0`，15 条多工具样本全部改为逐题显式参数和自包含问题，并通过所有冻结步骤的真实执行验证。

由于数据集发生变化，不能直接拿历史 `1.1.1` 的 `1/15` 与 M4.6A 比较。本报告在同一 `1.2.0` 数据集上重新运行 M4.5 control 和 M4.6A，确保唯一变量是多轮策略。

## 公平对照配置

- 日期：2026-07-23
- 模型：`deepseek-v4-flash`
- 数据集：`1.2.0`
- 样本：15 条多工具任务

## 逐条行为

M4.6A 在所有 15 条样本中都召回了完整的预期模型集合。新增多轮使以下 5 条样本从不合规变为合规：

- Fe2O3 解析、摩尔质量和单位换算；
- 摄氏度换算后计算热容；
- 温度换算后计算 Arrhenius 速率；
- 扩散距离计算后进行单位换算；
- Fe 的焓积分和熵积分。

边界控制在真实试验中均被触发并正常终止：

- 1 条达到 3 轮上限；
- 1 条达到 5 次调用上限；
- 1 条因完全相同的调用签名重复而停止；
- 其余 12 条由模型主动结束。

未通过严格路径的 7 条样本已经完整召回预期工具，主要失败原因是额外调用、参数字符串不完全一致，或模型先生成 ASCII 化学式导致反应工具拒绝后再修正。说明下一步瓶颈已经从“找不到后续工具”转移到“参数规范化与避免修正性调用”。

## 结论

M4.6A 达到预设的多工具路径合规率至少 40% 的门槛，且工具决策和模型选择没有退化。有界循环对依赖链有效，可以冻结为下一阶段基础实现。

代价同样明确：在仍携带全部 17 个工具 Schema 的情况下，多轮使 Token 增至 2.39 倍、延迟增至 1.79 倍。因此不应继续增加轮次上限。下一阶段应进入 M4.6B 候选模型召回，并保持本次 M4.5/M4.6A 两批结果作为消融对照。

全量 120 条语义回归尚未在 `1.2.0` 上执行；在 M4.6B 降低 Schema Token 后再运行完整基准更具成本效益。
