# M4.6B 候选模型召回实验

## 结论

M4.6B 通过预设门槛，可以替代 M4.6A 成为默认 autonomous 实验策略。

在同日、同模型、同数据集、同多轮提示词和相同轮次边界下，仅把每轮提供给大模型的工具 Schema 从全量 17 个改为 Top-K 候选集：

- 多工具路径合规率从 53.33% 提升到 66.67%；
- 工具决策准确率保持 100%；
- 总 Token 从 168,260 降至 59,282，减少 64.77%；
- 平均候选模型数从 17 降至 2.2；
- 15/15 实验完成，供应商失败为 0。

完整 120 例验证同样全部完成，语义通过率为 67.62%，总 Token 为 204,384。

## 实现契约

M4.6A 和 M4.6B 使用完全相同的多轮系统提示词，均保留最多 3 轮、累计最多 5 次工具调用和重复签名停止规则。两组实验的唯一策略差异是可见工具集合：

- `m4.6-v1`：全量 17 个工具 Schema，作为固定对照；
- `m4.6b-v1`：先执行 `lexical-card-v1` 召回，再提供 Top-5 候选 Schema。

召回器以冻结模型卡名称和显式领域别名为索引，记录每个候选的排名、分数、命中词和原因。策略边界如下：

- 命中模型时按得分排序并截取 Top-5；
- 存在计算意图但没有命中模型时，回退到全量 17 个模型；
- 没有工具信号时返回空候选集；
- 召回结果、回退原因和候选数量写入现有 LLM trace JSON，无需新增数据库表。

## 风险与下一步

当前召回器是可解释的静态词法策略，适合验证“缩小 Schema 集合是否有效”，但还没有覆盖真实用户表达分布，也没有通过重复实验估计模型方差。后续应：

1. 收集未命中和误召回语料，扩展为可版本化的混合召回，而不是直接增加 Top-K；
2. 进入 M4.6C，优先处理参数规范化、ASCII/Unicode 化学式和失败后的修正调用；
3. 对 M4.6B 至少重复 3 次核心子集实验，给出均值和方差；
4. 保留 `m4.6-v1` 作为全量 Schema 固定对照，不删除旧策略。
