# v1.1 CF-05 E3路由目录扩展计划v1

## 1. 目的

本计划把“至少扩展至136条”转换为目标级、可审核的关系槽位，但不自行编造新工具名称或契约：

```yaml
plan_id: V11-CF05-E3-ROUTING-EXPANSION-PLAN-V1-20260803
status: requirements_frozen_entries_unfilled
new_tool_entries_created: 0
external_api_calls: 0
```

## 2. 扩展规模的两种含义

- `136`：保证120规模双类型0/4/8替换池具有足够容量的数学下限；
- `190`：70个缺口槽完全不跨目标复用时的保守目录规模。

实际规模介于两者之间，但不能先假定一个工具可同时服务多个目标。每一条跨目标关系必须独立通过证据检查。

## 3. 70个未填充关系槽

| 目标 | 词法槽 | 契约错配槽 | 合计 |
|---|---:|---:|---:|

所有槽的初始状态均为`unfilled`，`candidate_tool_id=null`。这意味着模板只定义需要什么证据，不假装这些工具已经存在。

## 4. 新目录项准入条件

每个候选目录项必须具备：

- 独立工具ID、名称、语义API别名和科学功能；
- 结构化输入、输出和单位契约；
- 相态、温区、压力范围、系统、版本和可用性字段；
- 标准、原始文档、论文、软件手册或模型卡来源；
- 独立性证据；
- 至少一条目标近邻关系及不可替代证据。

契约错配近邻还必须提供“目标工具有效、候选工具因某个明确契约边界无效”的机器可复算测试夹具。

Schema-only目录项仍不能被称为可执行工具，也不能进入正式参数执行评分。
