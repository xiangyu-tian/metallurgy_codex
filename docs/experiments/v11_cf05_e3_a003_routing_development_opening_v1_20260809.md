# A003开发性路由开启包 v1

日期：2026-08-09

状态：`prepared_blocked_pending_method_implementation`

外部API调用：`0`

工具执行：`0`

## 1. 目的

在不扩大到完整4,800单元、也不接触独立验证集的前提下，冻结A003首轮开发性路由先导的最小平衡设计，用于校准四类预注册方法的实现与日志契约。该包不是确认性E3实验，也不支持H3/H4结论。

## 2. 冻结设计

本轮共96个开发单元：

```text
2个任务（同一Fe2O3问题的严格/宽松容差配对）
× 2个规模（17、120）
× 3个条件（none-0、lexical-8、functional_overlap-8）
× 2个工具池重复（A、B）
× 4种方法（Full Schema、Lexical Top-5、Dense Top-5、Hierarchical Top-5）
× 1次模型重复
= 96
```

这样保留了三个开发诊断轴：17→120规模端点、词法与高相似契约错配对比，以及严格/宽松可接受工具集合差异。C—E池、50/100规模、4近邻剂量和其余10条A003任务仍保留在候选数据中，待方法稳定后再决定是否进入扩大先导。

## 3. 防止金标泄漏

开启包将路由输入和离线评分表分开：

- `a003_routing_input_tasks.json`只含题目及分组信息；
- `a003_routing_scoring_registry.json`保存可接受工具集合和评分规则，只允许在响应落盘后离线使用；
- 96个运行单元不包含`acceptable_tools`、`scoring_rule`、`expected_parameters`等字段；
- 不访问40条独立验证集。

严格任务只接受`A003`；宽松任务按已经重算的任务容差接受`A003`或`E3C004`。这一区别只进入离线评分，不进入模型提示。

## 4. 方法就绪门

当前检查结果：

| 方法 | 状态 | 依据 |
| --- | --- | --- |
| Full Schema | ready | CF-06已证明17和120函数Schema可被API接受并返回原生函数调用 |
| Lexical Top-5 | pending | 现有`lexical-card-v1`只面向旧注册表，不能直接代表冻结120工具目录 |
| Dense Top-5 | pending | 尚无冻结的向量模型、向量快照和检索实现 |
| Hierarchical Top-5 | pending | 尚无冻结的领域→能力→适用域→工具级实现与配置 |

因此本包只完成设计开启，不生成外部请求载荷，也不创建运行授权。下一门槛是实现并哈希冻结三个Top-5方法，使其在完全相同的96单元上生成可复核的候选工具视图。

## 5. 统一第二阶段

四种方法使用同一选择提示、同一工具卡Schema和同一DeepSeek模型配置。Full Schema暴露整个池；三种Top-5方法只允许改变第一阶段候选召回，第二阶段选择提示保持相同。模型最多返回一次原生函数调用，不执行工具，不把纯文本回答计为正确选择。

## 6. 当前边界

- `functional_overlap`仍是冻结统计接口名称，当前证据实际为`contract_mismatch_proxy`，没有冶金专家确认，禁止确认性解释；
- 当前只有A003一个达到成对8/8近邻的目标工具，不能据此推广至多工具家族；
- 本轮不调用DeepSeek API、不执行冶金工具、不做显著性检验；
- CF-05保持`in_progress`，Core Frozen保持`false`。
