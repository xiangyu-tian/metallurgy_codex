这不是模型失败或路由方法失败，而是执行器的供应商线协议字段类型错误。

## 根因

执行器在请求体中发送：

```json
"thinking": "disabled"
```

DeepSeek 当前接口要求：

```json
"thinking": {"type": "disabled"}
```

这一结论由三类证据相互印证：64 条一致的服务端错误、仓库内既有可用适配器的实现，以及 DeepSeek 官方 Chat Completion 接口契约。

原假传输测试只检查了64条流程、零重试和零工具执行；假传输不会校验供应商JSON Schema，且当时没有对 `thinking` 的线格式做断言，所以未能在外部调用前捕获。
