日期：2026-08-11

## 1. 为什么先审计而不是直接构造最小差异任务

A002 和 A003 都接收：

```json
{"formula": "Fe2O3"}
```

表面上的功能描述分别是：

- A002：解析元素计量；
- A003：计算摩尔质量。

但 A002 的 verified contract 和运行结果不仅包含元素计量，还包含按冻结原子量计算的 `molar_mass`。如果在 A003 任务中把选择 A002 一律判错，就会制造不公平金标。

因此，本轮先回答：

> A002 是否实际上能够完成既有 A003 任务，以及它应属于主要可接受工具还是 Alternative Success？

## 2. 审计范围和政策

输入为2026-08-09冻结并重算过的12条 A003 开发任务。每条任务分别本地调用 A002 和 A003，共24次确定性工具调用。

冻结的主要可接受政策要求：

1. 单工具直接返回目标数值；
2. 数值落在任务预先冻结的绝对与相对容差内；
3. 运行结果显式返回 `unit=g/mol`。

Alternative Success 允许单位由 verified contract 明确给出，即使运行时结果没有单独的 `unit` 字段。两种政策分开报告，不允许用后置发现静默改变主要金标。

## 4. 工具关系结论

A002/A003 不是两个干净、对称、互斥的工具：

```text
A002：formula → elements + molar_mass + mass_fractions
A003：formula → molar_mass + unit
```

关系应定义为：

```text
asymmetric_output_overlap
```

方向为：

- A002 可以在数值层面完成 A003 的摩尔质量任务；
- A003 无法完成 A002 的元素计量输出任务。

所以该工具对适合作为“非对称重叠/替代成功”案例，不适合作为 H3 的对称近邻金标准。

## 5. 对120工具计数的影响

在工具独立性审核完成前，不应简单把 A002 和 A003 计为两个完全独立科学能力。建议暂时：

```text
family_relation = asymmetric_overlap
independent_count_contribution = pending
```

否则可能同时产生两类偏差：

1. 人为放大工具库规模；
2. 将能够正确回答的 A002 选择错误记为科学失败。
