## 2. 主要结果

| 方法 | 正确单元 | 正确率 | 调用单元 |
| --- | ---: | ---: | ---: |
| 始终不调用 | 78/81 | 96.30% | 0/81 |
| 始终调用验证工具 | 81/81 | 100.00% | 81/81 |
| 候选策略v1 | 81/81 | 100.00% | 12/81 |

候选策略在本次后置集中：

- 相对始终不调用提高3.70个百分点；
- 与始终调用的正确率相同；
- 避免69次无收益调用；
- 调用率为14.81%；
- 捕获3/3个已观察正收益单元。

这说明v1在当前独立题组上实现了预期的“有收益时调用、无收益时不调用”。由于样本量较小且不是正式确认性设计，不能把81/81外推为真实系统的普遍准确率。

## 3. 规则迁移

| 规则 | Gate任务 | No Tool | Forced Tool | 结果 |
| --- | ---: | ---: | ---: | --- |
| 严格版本化数值 | 4题/12单元 | 9/12 | 12/12 | 观察到正迁移 |
| 高动态范围重标度 | 0题/0单元 | — | — | 未评价 |
| 默认不调用 | 23题/69单元 | 69/69 | 69/69 | 未观察到漏失收益 |

严格版本化规则在4道独立任务中触发。正收益来自FeSO4严格版本题：No Tool三次均返回`151.904`，冻结常数参考值为`151.901`；Forced Tool三次均正确。该错误机制与开发集一致，即模型使用了非冻结版本的常用原子量。

需要谨慎解释：正收益集中在1道题的3次重复，而不是4道严格任务都出现错误。因此当前证据支持“该规则能捕获可复现的版本常数偏差”，但尚不足以精确估计严格版本任务的总体收益率。

Gate没有包含满足动态范围至少100且需要重标度的A004任务。因此，高动态范围规则仍保持“未独立评价”，不能因为策略总体81/81而宣布该规则通过。

## 4. 调用成本

| 条件 | 总Token | 平均延迟 |
| --- | ---: | ---: |
| No Tool | 11,226 | 778.88 ms |
| Forced Tool | 21,824 | 815.32 ms |

Forced Tool约为No Tool的1.94倍Token，平均延迟增加约36.44 ms。候选策略只在12/81个单元选择工具，因此相较始终调用显著减少Schema和回答Token暴露。

这里报告的是条件级实测成本。策略的实际端到端成本还需要在后续自主路由与参数生成实验中直接测量。

## 5. 这次结果证明了什么

当前结果支持：

1. “严格版本化常数 + 窄容差”是比“摩尔质量一律调用”更合理的边界；
2. 普通单位换算、化学式计数、教学近似摩尔质量、当前Gate中的普通归一化与简单杠杆定律，没有观察到强制调用收益；
3. 先冻结规则再打开后置题组的评价流程可执行；
4. 门控策略可以在保持本次正确率的同时减少大量无收益调用。

## 6. 这次结果没有证明什么

当前结果不证明：

- 所有冶金计算任务都适用该策略；
- A004高动态范围规则已经得到独立支持；
- 模型能够自主识别规则、选择工具并正确生成参数；
- 100多个相似工具下的路由已经解决；
- E1b或Core Freeze已经正式通过；
- 当前数据可以替代统计功效分析和正式确认性实验。

本次候选策略的`CALL_VERIFIED_TOOL`分支使用Oracle Parameters，隔离的是“验证工具可用性”的收益。参数生成、工具选择与端到端执行损失属于后续实验层，不能混入本结论。
