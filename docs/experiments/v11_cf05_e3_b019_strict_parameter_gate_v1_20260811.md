## 门控输入与规则

决策函数只使用：

- 用户请求文本；
- 已选择的工具编号；
- 模型生成的参数；
- 冻结的 B019 参数政策。

任务金标和 canonical inputs 不进入决策函数，只在门控结束后用于离线评价候选参数。

门控要求：

1. 请求必须能确定性提取总体成分、两相边界和 `fraction/percent` 标度；
2. 四个必需参数必须全部存在并与请求一致；
3. 禁止 `composition_basis=auto`；
4. 总体成分必须位于两相边界之间；
5. 两相边界不得相同；
6. 所有成分必须位于声明标度的合法范围；
7. `component` 只有在请求显式提供时才允许出现；
8. 未知参数、无法解析或证据冲突均进入 `review_required`。

## 回放结果

5 个原始调用未包含 `component`，门控保留原参数；11 个调用包含无依据的 `component="B"`，门控先阻断原调用，再删除该字段。离线评价显示，删除后的 16 组候选参数都与请求证据一致。

但“候选参数忠实”不等于“现在可以执行”。当前 B019 实现仍包含：

```python
params.get("component", "B")
```

因此，即使门控删除了无依据字段，运行时仍会在输出中重新补回 `"B"`。本轮将全部 16 个回放标记为：

```text
runtime_default_component_risk = true
execution_ready = false
```

这避免了“输入参数已经清理，所以工具可以安全执行”的错误升级。

## 边界挑战

12 条挑战覆盖：

- 合法 fraction 和 percent 请求；
- 无依据可选参数删除；
- 请求显式提供组元；
- 组元不一致；
- 缺少标度；
- 使用 `auto`；
- 数值与请求不一致；
- 两相边界相同；
- 总体成分位于连线外；
- 未知参数；
- 请求无法确定性解析。

全部挑战均产生预注册动作。只有显式给出并正确传递组元的挑战案例可达到 `execution_ready=true`。
