# A003 Hierarchical Top-5 候选实现 v1

日期：2026-08-09

状态：`candidate_implementation_passed_local_gate`

外部API调用：`0`

## 路由结构

该实现严格使用冻结工具Schema中的契约字段构建四层路径：

```text
scenario领域
→ scenario + core_method能力
→ main_input/main_output/boundary适用域
→ tool工具
```

领域和能力节点不是人工针对A003编写，也不读取`acceptable_tools`。领域节点来自`scenario`，能力节点来自同一领域内的`core_method`，适用域评分来自输入、输出、边界和参数描述。所有节点、成员关系及适用域签名均生成哈希快照。

## 固定策略

- 先在当前工具池上计算冻结词法基础分；
- 选择得分最高的3个领域；
- 在入选领域中选择8个能力节点；
- 在入选能力中进行适用域与工具级综合排序；
- 若裁剪后不足5个工具，依次从入选领域和全池基础排序回填；
- Top-K固定为5，并列按节点ID或工具ID升序。

该设计能够对层级裁剪路径进行逐单元复核，同时保持与Lexical Top-5相同的底层Token规范，避免把分词差异误当成层次化方法效果。

## 边界

当前只用于A003的24单元开发切片。只有在确定性、池内约束、金标隔离和开发Recall@5门均通过后，才能标记为候选实现通过；即使通过，也不自动获得外部API执行授权，更不构成H3/H4证据。

- 重复检索的层级路径、候选顺序和分数完全一致；
