# CF-05 E3 A002/A003 Top-5 视图开发记录

## 结论

16 条 A002/A003 最小差异任务、4 个 17/120 工具现实混合池和 3 种 Top-5 方法已形成 192 个本地检索单元。采用 Dense 查询策略 v2 后，Lexical Top-5、Dense Top-5 和 Hierarchical Top-5 均达到 64/64 的主可接受工具 Recall@5，满足构建后续开发性选择实验开启包的门槛。

本阶段没有调用外部 API、没有执行冶金工具，也没有访问独立验证集；结果只能用于开发和可行性验证，不能作确认性推断。

## Dense v1 缺口与复现审计

Dense v1 在 `E3-MP-FE2O3-ELEMENTS` 的两个 120 工具池重复中未将 A002 放入 Top-5，A002 均稳定排第 7，因而为 62/64。

三次独立进程审计表明：

- 查询向量哈希完全一致；
- 重新生成的 137 工具向量与既有冻结向量逐元素一致；
- 新旧索引的排序完全一致；
- 三次独立进程结果签名完全一致。

因此该缺口属于 Dense v1 查询任务表述与“文章检索”指令不匹配，而不是运行时漂移或索引损坏。

## Dense v2 选择

在开发集上按预先声明的规则比较四个查询指令候选：先最大化主可接受工具 Recall@5，再最大化最近主可接受工具的平均倒数排名，最后按预声明候选顺序破同分。

结果如下：

| 候选 | Recall@5 | MRR |
| --- | ---: | ---: |
| v1 文章检索指令 | 62/64 | 0.8743 |
| v2 直接输出工具指令 | 64/64 | 0.9219 |
| v3 直接任务工具指令 | 64/64 | 0.9219 |
| v4 无指令消融 | 64/64 | 0.8630 |

按规则选择 v2：`为这个问题检索能够直接产生所请求输出的专业计算工具：`。

这次升级只改变查询指令，不改变嵌入模型、工具契约文档、冻结向量索引、相似度或并列排序规则。v1 失败结果被保留为负向开发证据，未被覆盖。
